## Cloud deployment and OAuth

The sibling cloud stack's [README](../README.md) documents Docker/Pocket ID/HTTPS
operation. Its HTTP endpoint requires employee OAuth and exposes the 19-tool
`analytics` profile. Node.js 22.22.1+ is required by this checkout's updated dependencies.

Set `MCP_AUTH_MODE=oauth`, `MOYSKLAD_TOOL_PROFILE=analytics`, `MCP_AUTH_ISSUER`,
`MCP_AUTH_RESOURCE` (canonical /mcp URL), and `MCP_AUTH_JWKS_URI`; required scope
`MCP_AUTH_SCOPE` defaults to `moysklad:read`. HTTPS is required except explicit
localhost testing (`MCP_AUTH_ALLOW_LOCAL_HTTP=true`); Docker's private JWKS hop
can opt into HTTP using `MCP_AUTH_ALLOW_INTERNAL_JWKS_HTTP=true`. Partial OAuth
settings fail startup. Access tokens must have a matching issuer/audience/scope,
valid signature/time claims and no more than five minutes of remaining validity (plus five seconds for issuance rounding/clock drift). Pocket ID preserves `iat` through token refresh, so token age is not used as an expiry check. Protected
resource metadata is public; all MCP methods require a token. Secrets are mounted
from files in the cloud Compose stack. `MCP_AUTH_MODE=none` remains the standalone
local/stdio default; it does not protect a public HTTP endpoint.


Текущая версия содержит **71 инструментов** в профиле `full` и **19 инструментов чтения** в профиле `analytics`: компактные ответы, отчёты по размерам/ценам/категориям, рейтинг артикулов, сверку с прибыльностью, общий кеш снимков и планировщик запросов.

Доработки 3.3.0 запускаются **из собранного исходного кода этого репозитория**. Пакет `@theyahia/moysklad-mcp` и npm-значок ниже относятся к исходному проекту: команда `npx @theyahia/moysklad-mcp` не устанавливает наши локальные изменения. До отправки коммита на GitHub удалённая ветка также не содержит локальные изменения.

Сервер подключает ChatGPT и другие MCP-клиенты к JSON API 1.2 МойСклад: каталог и цены, остатки, контрагенты, заказы, отгрузки, приёмки, складские документы, возвраты, финансы, отчёты, аудит и вебхуки. Профиль `full` включает операции создания и изменения; `analytics` предназначен для отчётной сессии. Денежные входы и нормализованные ответы — в рублях; исключения: исходный `raw` и `get_dashboard` сохраняют единицы API (копейки). Запросы проходят через общий планировщик процесса.

## Быстрый старт

Для новой установки после публикации изменений в `dev`:

```bash
git clone --branch dev https://github.com/OWNER/moysklad-mcp.git
cd moysklad-mcp
npm ci
npm run build
```

Если репозиторий уже открыт локально, используйте его текущую рабочую копию. Для установки из исходников используйте Node.js 22 или 24: разработка и тесты требуют более нового Node, чем минимальная версия рантайма `>=22.22.1` в `package.json`.

### ChatGPT (локальный пилот или VPS)

ChatGPT подключается к серверу по Streamable HTTP. Для подключения нужен HTTPS-адрес вида `https://mcp.example.com/mcp`, доступный инфраструктуре OpenAI, и разрешение на добавление custom MCP в аккаунте или рабочем пространстве ChatGPT.

#### Локальный пилот (Windows, PowerShell)

**Запуск одной командой:** из каталога репозитория выполните:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start-local.ps1
```

Для отчётного пилота перед запуском задайте `$env:MOYSKLAD_TOOL_PROFILE = 'analytics'`. В этом профиле доступны 15 инструментов чтения; `list_stores` и `get_stock` входят только в `full`. Начните отчётный пилот с `list_organizations` или `search_products`.

Скрипт установит зависимости при первом запуске, соберёт сервер и запросит токен скрыто (или использует уже заданный `MOYSKLAD_TOKEN`). Токен не сохраняется в файл; `token.txt` скрипт запуска не читает. После завершения скрипт восстанавливает прежние значения `MOYSKLAD_TOKEN` и `HTTP_PORT`. Остановите сервер через `Ctrl+C`. Другой порт: добавьте `-Port 3001`; переустановка зависимостей: `-Reinstall`. Параметр `ExecutionPolicy Bypass` действует только для запускаемого процесса и не меняет системную политику.

Для ChatGPT оставьте сервер запущенным и выполните `ngrok http 3000` во втором терминале, как описано ниже.

**Ручной запуск:**

Установите Node.js версии, совместимой с `package.json`, и ngrok, настройте ngrok для своего аккаунта. В PowerShell откройте каталог клонированного репозитория и выполните:

```powershell
npm.cmd ci
npm.cmd run build

# Токен вводится скрыто и не попадает в историю команд.
$moyskladSecret = Read-Host 'MoySklad token' -AsSecureString
$env:MOYSKLAD_TOKEN = [System.Net.NetworkCredential]::new('', $moyskladSecret).Password
Remove-Variable moyskladSecret
$env:HTTP_PORT = '3000'
npm.cmd start
```

Оставьте сервер запущенным. Во втором терминале проверьте его и откройте HTTPS-туннель:

```powershell
Invoke-RestMethod http://127.0.0.1:3000/health
ngrok http 3000
```

Скопируйте HTTPS-адрес из ngrok и добавьте `/mcp`, например `https://your-subdomain.ngrok.app/mcp`. Используйте этот URL в шагах подключения ChatGPT ниже. `localhost` и `127.0.0.1` в поле Server URL ChatGPT не подойдут: запросы приходят из инфраструктуры OpenAI.

**Туннель публикует сервер без встроенной авторизации.** Для краткого пилота с **отдельным тестовым аккаунтом МойСклад без реальных бизнес-данных** можно выбрать в ChatGPT **No authentication**. Для своего рабочего аккаунта сначала настройте защиту доступа, описанную ниже; непредсказуемый URL туннеля не заменяет авторизацию. Не открывайте порт 3000 для внешних или локальных сетей — текущий сервер слушает не только loopback.

Начните с `list_stores` или `get_stock`. Компьютер, сервер и туннель должны оставаться включёнными; при изменении URL обновите подключение ChatGPT. Чтобы завершить пилот, остановите ngrok и сервер через `Ctrl+C`, затем в терминале сервера удалите переменные:

```powershell
Remove-Item Env:MOYSKLAD_TOKEN, Env:HTTP_PORT
```

Файлы `.env` и `token.txt` автоматически не загружаются сервером. `token.txt`, `.env*` и `.tools/` исключены из Git (кроме возможного `.env.example`). Назначение HTTPS-адреса и подключение описаны в [официальной инструкции OpenAI](https://developers.openai.com/api/docs/guides/custom-mcp-server).

#### Развёртывание на VPS

**Подготовка на VPS (Linux, Bash):** установите Node.js версии, совместимой с `package.json`, и выполните в каталоге клонированного репозитория:

```bash
npm ci
npm run build

# Введите токен МойСклад без отображения на экране и записи в историю команд.
read -rsp 'MoySklad token: ' MOYSKLAD_TOKEN
echo
export MOYSKLAD_TOKEN
HTTP_PORT=3000 npm start
```

Это запуск в текущем терминале; для постоянной работы настройте systemd или контейнер с передачей секрета через окружение. Файл `.env` автоматически не загружается. Проверить процесс можно на VPS: `curl http://127.0.0.1:3000/health`. Для отчётного профиля задайте `MOYSKLAD_TOOL_PROFILE=analytics`. На VPS с публичным HTTPS-доменом ngrok не нужен: reverse proxy направляет `/mcp` на локальный порт 3000. Готовые systemd/container/OAuth-конфигурации в репозиторий не входят.

**Перед подключением клиента:** настройте домен, HTTPS reverse proxy на порт 3000 и защиту доступа, совместимую с ChatGPT. Текущая реализация `/mcp` **не проверяет авторизацию входящих запросов и не реализует OAuth**: любой, кто достигнет эндпоинта, сможет вызвать инструменты с правами серверного токена МойСклад. Для рабочего подключения с пользовательским входом потребуется OAuth-совместимый шлюз или доработка сервера. Закройте прямой внешний доступ к порту 3000; HTTPS и CORS сами по себе не ограничивают доступ.

#### Подключение в ChatGPT (веб)

1. Откройте **Plugins**, нажмите **+ → Add custom MCP server**.
2. Укажите имя `МойСклад` и **Server URL**: HTTPS-адрес туннеля с `/mcp` для локального пилота или `https://mcp.example.com/mcp` для VPS (замените домен своим).
3. Настройте **OAuth** в соответствии с вашим шлюзом. Токен `MOYSKLAD_TOKEN` остаётся в окружении сервера; он не является OAuth-токеном для входа клиента. **No authentication** допустим для отдельного тестового аккаунта в кратком пилоте либо при наличии отдельной, проверенной защиты доступа.
4. Ознакомьтесь с предупреждением о доступе и нажмите **Create as a plugin**, затем установите созданный плагин. Доступность подключения зависит от разрешений аккаунта и рабочего пространства.
5. В новом чате введите `@`, выберите `МойСклад` и начните с запроса на чтение: «Покажи организации через list_organizations». В профиле `full` также можно запросить склады через `list_stores`.

После настройки клиент работает в обычном чате ChatGPT. В настройках подключения включите только необходимые инструменты и проверяйте подтверждения операций, изменяющих заказы, остатки или платежи.

Для рабочего аккаунта инструкция предполагает защищённое развёртывание; этот блок не добавляет авторизацию в сервер. Интеграция ещё не проверена в ChatGPT.

Официальная документация OpenAI: [подключение custom MCP server](https://developers.openai.com/api/docs/guides/custom-mcp-server), [аутентификация MCP](https://developers.openai.com/plugins/build/auth).

## Авторизация

| Переменная                             | Описание                       |
| -------------------------------------- | ------------------------------ |
| `MOYSKLAD_TOKEN`                       | Bearer-токен (предпочтительно) |
| `MOYSKLAD_LOGIN` + `MOYSKLAD_PASSWORD` | HTTP Basic-авторизация         |

Токен выдаётся в МоёмСкладе: **Настройки → Пользователи → Токены доступа** (также работает `POST /security/token` с Basic-авторизацией). Генерация нового токена отзывает предыдущий.

**Нужные права:** у пользователя или токена должен быть доступ к тем сущностям, с которыми вы работаете. Читающим инструментам нужны права просмотра, создающим и изменяющим — права редактирования соответствующего типа документов. Вебхуки и часть отчётов требуют платного тарифа МойСклад.

## Цены

API МойСклад хранит деньги в **копейках** (1 рубль = 100 копеек). Сервер конвертирует автоматически:

- **На вход**: передавайте цены и суммы **в рублях** (например, `1500.50`)
- **На выход**: нормализованные цены и суммы возвращаются **в рублях**; исходные ответы `raw` сохраняют единицы API
- (Отчёт `get_dashboard` проксируется как есть, поэтому денежные значения в нём остаются в копейках.)

Если у товара есть цена продажи, МойСклад требует **тип цены**. Сервер сам подставляет тип цены по умолчанию из вашего аккаунта (берёт из `list_price_types`); чтобы выбрать конкретный, передайте `price_type_href`.

## Периоды, продажи и полнота отчётов

`get_sales_report` и `get_profit_report` используют `/report/profit/byproduct`; `get_turnover` — `/report/turnover/all`. Период передаётся отдельными query-параметрами `momentFrom` / `momentTo`, а не внутри `filter`.

- `moment_from` / `moment_to`: `YYYY-MM-DD` или `YYYY-MM-DD HH:mm:ss` (также допустимы разделитель `T` и миллисекунды `.SSS`). Дата без времени означает начало дня для `moment_from` и `23:59:59.999` для `moment_to`. Полное время сохраняется; неправильные даты и обратный период отклоняются.
- Значения передаются в часовом поясе отчёта API МойСклад без преобразования. Сервер не передаёт `X-Lognex-Accept-Timezone`; локальный часовой пояс компьютера не применяется. Строки с `Z` или UTC-смещением не принимаются: укажите время в формате API.
- `sell_quantity` / `sell_sum_rubles` — продажи до вычитания возвратов. `return_quantity` / `return_sum_rubles` — возвраты отдельно; в отчёте продаж `net_quantity` / `net_sum_rubles` — разность. Товары, комплекты и услуги включены; модификации агрегированы в родительские товары. В компактном ответе для соединения с каталогом используйте `id` и `type`, а не название. Совместимые `product_id`, `product_type` и `product_href` доступны при `fields: "full"`. Основание возвратов в этих двух отчётах — `return_price_basis: "api_profitability_report"`.
- Продажи основаны на отчёте прибыльности МойСклад (отгрузки и розничные продажи), а не на заказах. Правила учёта документов определяет API отчёта. Без `organization_href` охватываются все доступные токену организации; с ним добавляется фильтр по юрлицу.
- Ответ — одна страница: `total` — число строк всего, `returned` — на этой странице, `next_offset` — следующая страница либо `null`. Для полного отчёта запрашивайте все страницы с тем же периодом и фильтром.

`search_products` по умолчанию возвращает компактные строки `analysis`: `id/type/name/article`, `path_name`, `folder_id`, `archived` и цены. `fields: "quantity"` возвращает ровно четыре поля идентичности. Для архивных товаров задайте `archived: true`; для активных — `false`. Чтобы собрать оба набора, выполните оба запроса с пагинацией. Полный объект `product_folder` раскрывается только при `fields: "full"` и `limit <= 100`; на больших страницах остаётся ссылка. `get_product` использует отдельный флаг `raw: true`, а не общие параметры `detail/fields/output`.

`get_documents` принимает только `expand: "positions"` или `"positions.assortment"` (при раскрытии `limit <= 100`). В каждой строке появляется единственный массив `positions_export.items`. `get_document` по умолчанию раскрывает `positions.assortment`, возвращает краткую шапку и нормализованные позиции. Исходный документ с `positions.rows` доступен только при `detail: "raw"`; одновременно второй массив не добавляется. MCP-результат содержит текст в `content`, без копии в `structuredContent`.

**Позиции могут быть неполными:** проверяйте `positions_export.total`, `returned`, `complete` и `next_offset`. Для остальных страниц вызовите `get_document` с `positions_limit` (1–100) и `positions_offset`; повторяйте до `next_offset: null`. `complete: true` означает, что в одном ответе есть все позиции с начала списка. Последняя отдельная страница при ненулевом offset не является полным документом. Не считайте неизвестный `total` доказательством полноты.

Документация API: [Прибыльность](https://github.com/moysklad/api-remap-1.2-doc/blob/master/md/reports/_report_pnl.md), [Обороты](https://github.com/moysklad/api-remap-1.2-doc/blob/master/md/reports/_report_turnover.md).

### Компактные ответы и аналитика (3.3.0)

| Инструмент                     | Результат                                                                                                        |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| `get_sales_by_size`            | Серверный расчёт по всем страницам проведённых продаж и возвратов; по умолчанию 12 размеров 24–46 с шагом 2      |
| `get_sales_by_price`           | Распределение по точным диапазонам фактической цены позиции после скидки                                         |
| `get_sales_by_category`        | Продажи, возвраты, net и доли трёх явно классифицированных категорий без ограничений размера/цены                |
| `get_sales_ranking_by_article` | Рейтинг по точному артикулу родительского товара; по умолчанию топ-20 продаж                                     |
| `reconcile_sales`              | Сверка количества с прибыльностью: итоги, число расхождений, до 10 примеров; сравнение денег включается отдельно |
| `read_report_export`           | Чтение страницы ранее созданного MCP-экспорта, по умолчанию 25 строк                                             |
| `get_mcp_diagnostics`          | Безопасные события запросов, cooldown и состояние кеша источников; по умолчанию 5 событий                        |

`detail: "summary" | "rows" | "raw"`, `output: "inline" | "file"` и `fields: "quantity" | "analysis" | "full"` доступны в универсальных документах, поиске каталога и отчётах продаж/прибыли/оборотов. По умолчанию эти инструменты возвращают компактные строки, страницы — по 25. `summary` списка/обычного отчёта относится к запрошенной странице, а не ко всему периоду. `raw` возвращает исходные данные API; `fields` в нём не применяется. Набор `quantity` убирает деньги из нормализованных строк. `full` сохраняет старые поля, но не заменяет явный `raw` для полной карточки.

В компактном контракте 3.3.0 номенклатура имеет одно обозначение: `id`, `type`, `name`, `article`. Количественная строка товара содержит только эти четыре поля; строки отчётов добавляют свои количества. У модификации отдельно есть `parent_product_id`, `size`, `size_raw`. В позиции документа `position_id` обозначает строку, `id` — её номенклатуру. `analysis` добавляет необходимые характеристики, путь и `folder_id`, без раскрытой папки, владельца или URL. **Совместимые `assortment_id`, `product_id`, повторяющиеся имена/ссылки и полный объект папки доступны в `fields: "full"`. Старое `product_id` означает ID номенклатуры, включая модификацию, а не родителя.** Для потребителя контракта 3.2.0 явно передавайте `fields: "full"`.

Выбранные `characteristics` в analysis/full по умолчанию содержат «Размер»; в поиске модификаций/ассортимента есть `characteristic_names`. `size_raw` сохраняет исходное значение, `size` извлекает число из «36 (140-145)». Отсутствующие выбранные сведения — `null`; артикул, название и рост не используются вместо размера. Артикул — исходная строка с ведущими нулями и исходным написанием, code не подставляется. Компактные строки продаж также включают `article`; при необходимости карточку читает сервер.

Для аналитики обязательны `moment_from`, `moment_to`; `organization_hrefs` ограничивает организации, отсутствие или пустой список означает все доступные токену. Даты без времени включают весь день; явное время сохраняется, часовой пояс — как в API МойСклад. Учитываются только `applicable=true`: `demand`, `retaildemand`, `salesreturn`, `retailsalesreturn`. Все страницы документов и позиций читаются на сервере; неполные или изменившиеся итоги страниц завершают расчёт ошибкой. `net = sold - returned` — количество после возвратов за период, **не остаток на складе**. Товарные карточки берутся на момент проверки, исторического каталога API не предоставляет.

Пример `get_sales_by_size`:

```json
{
  "moment_from": "2024-01-01",
  "moment_to": "2024-01-31",
  "size_min": 24,
  "size_max": 46,
  "size_step": 2,
  "fields": "quantity"
}
```

У агрегатов по умолчанию `summary`: массив только итоговых размеров/диапазонов, `sold`, `returned`, `net`, `excluded`, `unresolved`, `out_of_scope` и контроль `accounting`. В отчёте размеров значения строк расположены в порядке массива `categories`. `detail: "rows"` или `"raw"` у этих двух инструментов добавляет нормализованную расшифровку, а не исходные документы API; повторяемые признаки товаров вынесены в `dictionary`, позиции ссылаются на него через `assortment_ref`.

Категории: `female_sleeveless`, `female_sleeved`, `male`. По умолчанию область — название родительского товара содержит «купальник»; исключаются комплекты и плавание. Настройки: `scope_name_contains`, `exclude_name_contains`, `exclude_path_contains`, `categories`. Пол определяется явным названием/группой, рукав — последовательно по группе, названию, текстовым/SEO-полям. Бренд не определяет рукав. Если признаков нет или они противоречат друг другу, строка попадает в `unresolved`. Ручная классификация задаётся в `category_overrides` с ID товара, категорией и обязательным `evidence`.


Пример `get_sales_by_price`:

```json
{
  "moment_from": "2024-01-01",
  "moment_to": "2024-01-31",
  "bands": [
    {
      "id": "short_1000_2000",
      "category": "female_sleeveless",
      "min": "1000",
      "max": "2000",
      "include_min": true,
      "include_max": false
    },
    {
      "id": "short_2000_3000",
      "category": "female_sleeveless",
      "min": "2000",
      "max": "3000",
      "include_min": true,
      "include_max": true
    }
  ],
  "return_price_basis": "return_document",
  "output": "file"
}
```

Границы — десятичные строки в рублях. Диапазоны одной категории не могут пересекаться; вне них количество идёт в `outside`, неизвестная цена — в `unresolved`. Цена `net_unit_price` вычисляется как `price / 100 × (100 - discount) / 100` десятичной арифметикой с точностью 80 значащих цифр. Сравнение выполняется до округления: **12500.006 > 12500**, даже если отображение округлено до двух знаков `ROUND_HALF_UP`. Денежные значения JSON API сначала прочитаны как JavaScript number: утраченную самим входным JSON точность восстановить нельзя. Средняя цена товара не используется. Отсутствующая цена/скидка не заменяется нулём. Для возвратов используется цена и скидка **документа возврата**; основание исходной продажи пока не поддерживается. Расчёт рассчитан на документы в RUB, конвертация других валют не реализована.

Файловый ответ содержит сводку и `resource_link` с `moysklad-export://…`, без локального пути и большого массива. MCP-клиент может выполнить `resources/read` для полного JSON или `read_report_export` с `uri`, `section: "detail" | "dictionary" | "positions" | "rows" | "documents" | "variants" | "products" | "assortment" | "items" | "bundles" | "services"`, `limit` (1–100) и `offset`. Для исходного `raw`-списка используйте секцию `rows`. Экспорт живёт час и до перезапуска сервера; при потере нужно сформировать его повторно. Это ресурс MCP, не публичная HTTP-ссылка для скачивания браузером. В файловом режиме `summary` не удаляет расшифровку из файла; документ/каталог сохраняет только запрошенную страницу, её полнота явно указана.

`total`, `returned`, `next_offset`, `complete` показывают полноту страницы; неизвестный итог — `total: null`, `complete: false`. Агрегаты возвращают `complete: true` только после чтения всех исходных страниц. В сверке `complete` относится к расчёту, а `examples` ограничен `example_limit`. Неравенство суммы диапазонов общему итогу объясняется `outside`, `unresolved`, `excluded`; для размеров — исключёнными размерами/категориями.

Каталог аналитики кешируется в памяти на 5 минут отдельно для учётных данных. Ответ содержит `catalog.version`, `checked_at`. `refresh_catalog: true` обходит кеш; изменение `updated` в раскрытой карточке также обновляет запись. Карточки не передаются модели повторно в кратком ответе.

Документы/позиции кешируются отдельно: период + нормализованные организации + учётные данные, без категории/размера/цены в ключе. Рейтинг, категории, размеры, цены и сверка разделяют один снимок. Ответ содержит `snapshot.id`, `captured_at` (начало загрузки), `loaded_at`, `expires_at`, `reused`. Срок — 5 минут после завершения загрузки, максимум 8 снимков в памяти; совпадающие параллельные запросы разделяют одну загрузку. В снимке заморожено и обогащение каталога. `refresh_source: true` перечитывает документы/позиции. `refresh_catalog: true` обновляет карточки действующего снимка без скачивания документов и без продления их срока. Для полного обновления передайте оба флага. Смена учётных данных/организаций/периода или истечение срока исключает переиспользование. Для услуг/комплектов карточки дополнительно не читаются; остальные товары нужны для классификации и совместной сверки.

После обновления остановите старый процесс и запустите `start-local.ps1` снова. `/health` должен показывать **3.4.1**, `tool_profile` и `tools`: **71** для `full`, **19** для `analytics`. HTTP-тест проверяет свежий `tools/list`, страницы/режимы и оба профиля. В ChatGPT откройте подключение в **Plugins**, нажмите **Refresh**, проверьте новые инструменты/параметры и начните новый чат — это [официальный порядок обновления метаданных](https://developers.openai.com/plugins/deploy/connect-chatgpt). Если в вашем интерфейсе нет Refresh, переподключите сервер с тем же URL/настройками. Проверка свежего серверного списка не подтверждает автоматически работоспособность конкретной клиентской сессии.

Проверка исходников: `npm run build`, `npm test`, `npm run lint`. Для интеграционных проверок используйте собственные приватные тестовые данные.

### Рейтинг, категории и профиль отчётной сессии

Новые инструменты: `get_sales_ranking_by_article`, `get_sales_by_category`, `get_mcp_diagnostics`.

Пример запроса рейтинга:

```json
{
  "moment_from": "2024-01-01",
  "moment_to": "2024-01-31",
  "categories": ["female_sleeveless", "female_sleeved"],
  "quantity_basis": "sold",
  "top_n": 20,
  "offset": 0
}
```

Рейтинг группирует точную строку `product.article`, объединяя модификации и разные товары с одним артикулом. Сортировка: выбранное количество по убыванию, затем артикул по кодовым единицам строки без локали. `quantity_basis: "sold" | "returned" | "net"`; `top_n` — размер страницы 1–100, `offset` — смещение полного рейтинга. `total/returned/next_offset/complete` относятся к странице рейтинга; `source_complete` — к полноте прочитанных источников. Пустые/отсутствующие артикулы отдельно в `missing_articles`; товар с одними возвратами остаётся в учёте. `output: "file"` сохраняет `detail`, `dictionary`, весь `ranking`; `read_report_export` поддерживает также `section: "ranking"`.

Категории принимают тот же период, организации, классификацию и `quantity_basis`, без top_n/offset и **без ограничений размера или цены**. По умолчанию три строки. Процент = единицы категории / единицы запрошенных явно классифицированных категорий × 100; знаменатель/основание и исключение unresolved/excluded указаны в `denominator`. Для net используются net-единицы; отрицательные значения сохраняются, при нулевом знаменателе процент `null`. Округление десятичное HALF_UP до двух знаков; сумма округлённых долей может отличаться от 100.00.


Схемы всех 67 инструментов тоже занимают контекст. Для отчётных задач доступен явный профиль **15 инструментов**:

```powershell
$env:MOYSKLAD_TOOL_PROFILE = 'analytics'
.\start-local.ps1
```

Полный профиль — `MOYSKLAD_TOOL_PROFILE=full` или отсутствие переменной. Analytics публикует только:

- `search_products`, `search_variants`, `search_assortment`;
- `get_document`, `get_documents`, `list_organizations`;
- `get_sales_report`, `get_profit_report`;
- `get_sales_by_size`, `get_sales_by_price`, `get_sales_by_category`, `get_sales_ranking_by_article`;
- `reconcile_sales`, `read_report_export`, `get_mcp_diagnostics`.

Создающие инструменты не публикуются. Перезапустите процесс и обновите подключение после смены профиля. `/health` показывает профиль и фактическое число инструментов. По умолчанию полный профиль сохранён для совместимости.

Для сравнения точности и объёма ответов используйте синтетические данные и учитывайте схемы инструментов, страницы экспорта и сетевую задержку. Производственные результаты не включаются в документацию.

### Лимиты API и диагностика

Проверенные новые значения по умолчанию: `MOYSKLAD_RATE_BUCKET=8`, `MOYSKLAD_MAX_CONCURRENT=2`. Запросы запускаются равномерно: интервал 3000/budget миллисекунд на единицу веса, складские отчёты all/bystore имеют вес 5. Заголовки API могут дополнительно замедлить темп. Общий планировщик всех операций одного процесса на 429/5xx удерживает всю очередь. Учитываются X-Lognex-Retry-After, X-Lognex-Reset, Retry-After (секунды/HTTP-date), limit/remaining/interval. Backoff минимум 1 секунда, затем 2, поэтому короткий заголовок не вызывает немедленный burst. Код 1073 снижает параллелизм до 1. [Официальные заголовки и ограничения](https://dev.moysklad.ru/doc/api/remap/1.2/).

Максимум 3 попытки, ожидание очереди — до 60 секунд. Длинный server cooldown не обрезается: вместо раннего запроса возвращается `RATE_WAIT_EXHAUSTED` с указанием повторить позже. Исчерпание попыток даёт короткий API_HTTP_429/API_HTTP_5xx/API_TIMEOUT и `isError: true`, без успешного частичного отчёта. Ошибки не включают тело ответа API, запросы или stack trace. Достаточных заголовков исторических 429 не сохранилось; их причина остаётся неподтверждённой.

Несколько процессов/воркеров и интеграций с теми же учётными данными делят внешний лимит API, но **не эту очередь**. Проверенная конфигурация — один процесс MCP; при внешней конкуренции уменьшайте бюджет/параллелизм или применяйте внешний общий лимитер. Произвольная внешняя нагрузка не покрыта гарантией.

По явному запросу `get_mcp_diagnostics` возвращает до 20 последних событий (`last_events`, по умолчанию 5): status, duration, attempt, weight, числовые безопасные заголовки, cooldown, счётчики снимков. События 429 пишутся в stderr автоматически; `MOYSKLAD_DIAGNOSTICS=1` включает все события. Ключи, URL/параметры, бизнес-ответы и stack trace не пишутся. При загрузке всего ресурса в контекст модели **экономия на экспортированном массиве исчезает**.

## HTTP-транспорт

```bash
HTTP_PORT=3000 node dist/index.js
# или
node dist/index.js --http 3000
```

Команды выполняются после сборки. Без `HTTP_PORT` и `--http` сервер использует stdio. HTTP-транспорт создаёт отдельную пару MCP server/transport для каждого запроса и возвращает JSON; кеш и планировщик общие для процесса. Эндпоинты: `POST /mcp` (JSON-RPC), `GET /health` (статус), `OPTIONS /mcp` (CORS). Для POST клиенту нужны `Content-Type: application/json` и `Accept: application/json, text/event-stream`. Долговременный поток GET не поддерживается. CORS **выключен по умолчанию** — HTTP-эндпоинт действует от имени вашего токена МойСклад, поэтому задавайте `MOYSKLAD_HTTP_CORS_ORIGIN` только если доверенному браузерному origin это действительно нужно.

## Конфигурация (переменные окружения)

| Переменная                             | По умолчанию | Описание                                                          |
| -------------------------------------- | ------------ | ----------------------------------------------------------------- |
| `MOYSKLAD_TOKEN`                       | —            | Bearer-токен                                                      |
| `MOYSKLAD_LOGIN` / `MOYSKLAD_PASSWORD` | —            | Basic-авторизация                                                 |
| `MOYSKLAD_RATE_BUCKET`                 | `8`          | Бюджет веса за 3 секунды; равномерный запуск запросов             |
| `MOYSKLAD_MAX_CONCURRENT`              | `2`          | Параллельные запросы одного процесса, максимум 5                  |
| `MOYSKLAD_TOOL_PROFILE`                | `full`       | `full` (67 инструментов) или `analytics` (15 инструментов чтения) |
| `MOYSKLAD_DIAGNOSTICS`                 | —            | `1`: все безопасные события в stderr; события 429 пишутся всегда  |
| `MOYSKLAD_HTTP_CORS_ORIGIN`            | —            | Разрешённый CORS-origin для HTTP-транспорта                       |
| `HTTP_PORT`                            | —            | Запустить транспорт Streamable HTTP на этом порту                 |

## Ограничение частоты запросов

Все запросы одного процесса используют общую FIFO-очередь: по умолчанию 8 единиц веса за 3 секунды и 2 параллельных запроса. Это равномерный планировщик с общей паузой по ответам API; отчёты `get_stock` и `get_stock_by_store` стоят по 5 единиц. Подробности повторов, заголовков и диагностики приведены в разделе «Лимиты API и диагностика». Лимиты аккаунта определяет API; при конкурирующих интеграциях уменьшайте локальные настройки.

## Решение проблем

| Симптом                                 | Причина и что делать                                                                                                                            |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `Auth not configured`                   | Задайте `MOYSKLAD_TOKEN` (или `MOYSKLAD_LOGIN` + `MOYSKLAD_PASSWORD`).                                                                          |
| `API_HTTP_401` / `API_HTTP_403`         | Проверьте токен и права пользователя на сущность.                                                                                               |
| `API_HTTP_412`                          | Проверьте обязательные поля и ссылки документа; например, `expense_item_href` у платежа. Ответ содержит безопасный код API, без исходного тела. |
| `API_HTTP_429` / `RATE_WAIT_EXHAUSTED`  | Повторите позже, проверьте `get_mcp_diagnostics` и другие интеграции; уменьшите бюджет/параллелизм.                                             |
| `API_TIMEOUT` / `API_NETWORK_ERROR`     | Проверьте доступ сервера к API МойСклад и повторите запрос.                                                                                     |
| Старый список инструментов в ChatGPT    | Перезапустите сервер, проверьте `/health`, обновите подключение через Refresh и откройте новый чат.                                             |
| GET `/mcp` → 406, OAuth discovery → 404 | Проверяйте POST initialize/tools/list. GET-поток и OAuth discovery не реализованы; эти строки сами по себе не доказывают сбой MCP.              |
| `EXPORT_NOT_FOUND`                      | Экспорт истёк или сервер перезапущен; сформируйте его повторно.                                                                                 |
| `HTTP 415`                              | Среда выполнения не отправляет gzip — используйте Node ≥18 (его `fetch` делает gzip автоматически).                                             |
| Вебхуки и часть отчётов не работают     | Требуют платного тарифа МойСклад.                                                                                                               |

## Разработка

```bash
npm install        # зависимости + git-хуки (husky)
npm run build      # tsc -> dist/
npm run lint       # eslint
npm run typecheck  # tsc --noEmit
npm test           # vitest (требуется Node >=20)
npm run coverage   # vitest с покрытием
```

`package.json` задаёт минимальный рантайм **Node ≥22.22.1**. Для этой рабочей копии и её тестовой оснастки используйте **Node 22 или 24**; Vitest допускает также Node 20.
