# Проверка требований: MCP МойСклад 3.3.0

10.10.2026. Основание: [документ требований](REQUIREMENTS-3.3.0.md). Ранее работающая аналитика, точные цены, раздельные продажи/возвраты/net, доступные ресурсы и постраничное чтение сохранены. Полный профиль публикует 67 инструментов; отчётный профиль analytics — 15. Изменения локальные, без публикации npm/VPS.

## Надёжность и свежие данные

[reliability-live-3.3.json](reliability-live-3.3.json): read-only запуск с ранее разрешённым token.txt, **8 единиц/3 секунды, 2 параллельных запроса**, один процесс. Холодный источник: **188 126 мс**, 788 отгрузок + 60 возвратов, 2496 позиций. Затем четыре отчёта: **54 мс, 0 дополнительных API-запросов**, общий snapshot.id. Сверка: **0 расхождений, 354 номенклатурные строки**.

За этот запуск — 363 API-запроса, 0 ответов 429. Это один успешный запуск (1/1), не статистическая гарантия для любой нагрузки. Последние 20 безопасных событий сохранены: status 200, X-RateLimit-Limit 45, remaining 42, interval 3000 ms, reset/retry_after 0; фактический локальный pacing 375 ms/weight. Наблюдения подтверждают текущую успешную конфигурацию, не причину прежнего сбоя.

В 3.2.0 были подтверждены технические ограничения: выдача пачки из фиксированного окна, индивидуальная пауза повтора, короткий header мог привести к почти немедленному повтору; остальные операции продолжали отправку. В 3.3.0 shared cooldown останавливает запуски всей очереди, следующий старт распределяется по времени. Заголовки большой паузы не обрезаются до раннего повторного запроса: есть ограничение ожидания очереди с корректной ошибкой. API-код 1073 снижает concurrency до 1. Поле weight учитывает прежние складские веса 5 и явно переданный вес, без двойного списания.

Несколько процессов/другие интеграции с одинаковыми учётными данными разделяют внешний лимит, но не память планировщика. Проверенная конфигурация — один процесс; внешнюю нагрузку надо учитывать отдельным общим лимитером или снижением бюджета. Временная ошибка никогда не возвращает complete/успешный частичный отчёт и не записывает частичный источник в кеш.

## Проверки

`npm.cmd run build`, `npm.cmd run lint` проходят. **159 тестов, 14 файлов**. Новые tests/scheduler.test.ts, tests/rankings.test.ts, tests/september.test.ts; обновлены HTTP/projection/client regressions. Каталожный refresh, поступивший во время загрузки источника, проверен отдельно: обновляет карточку без второй загрузки документов.

Проверены global 429 cooldown, отсутствие retry burst при header 1 ms, длинный Retry-After/HTTP-date, depleted remaining=0, adaptive pacing, stock weights, concurrency code, исчерпание попыток и безопасные числовые логи. Также: exact boundaries/12500.006, discounts/return-doc price, counts balance, categories/unknown scope, leading zeros/стабильные ties, missing article, negative/zero net denominator, quantity projection без nested ownership, parent-size fallback, resource expiry/credentials/page, source cache scope/expiry/refresh/in-flight/failure и свежие tools/list обоих профилей.

Розничных документов в текущем месяце нет; реальная retail-ветка, реальные одновременные refresh с разными флагами и нагрузка нескольких процессов не проверены живыми бизнес-данными. Даты и страницы покрыты сохранёнными регрессиями; существующие ограничения валют/исторических карточек описаны в README.

## Измерения полного MCP-содержимого

[benchmark-3.3.json](benchmark-3.3.json): `js-tiktoken/o200k_base`. Исполнены сохранённые **реальные compiled handlers 3.2.0** и текущие 3.3.0 на одной обезличенной фикстуре; response не реконструирован. У папки синтетические owner/group metadata для проверки projection. Указанные величины — наблюдение одного запуска, URI/timestamps могут немного менять число токенов при повторе.

Каждый сценарий учитывает все предложенные runtime tools/list schemas, все объявленные MCP-запросы/результаты, resource_link и follow-up чтение страницы. API 429 обрабатывается внутри сервера и не добавляет модельных сообщений; в этом trace MCP retries=0, failures=0. Recovery/exhaustion проверены отдельными simulated tests. Скрытые OpenAI prompt/framing/reasoning и реальные фильтры инструментов пользовательского клиента недоступны и не включены: **это controlled MCP trace, не полный биллинг реальной сессии ChatGPT**.

| Завершённая задача               | 3.2.0, 64 схемы | 3.3.0 full, 67 схем | 3.3.0 analytics, 15 схем |
| -------------------------------- | --------------: | ------------------: | -----------------------: |
| Quantity products, 25 строк      |          18 480 |              15 020 |                    6 015 |
| Женский top-20 + supporting page |          82 768 |              16 056 |                    7 035 |
| Три категории + supporting page  |          14 218 |              15 487 |                    6 498 |
| Размеры + цены                   |          15 527 |              17 054 |                    8 049 |

Все числа в таблице — **токены полного trace за задачу**, а не символы. В JSON отдельно есть characters/bytes_utf8, execution_ms, failure count, API requests, число MCP messages и resource reads.

Например, quantity-products полный trace: 3.2.0 — **79 627 символов / 81 184 UTF-8 байта**, 3.3.0 analytics — **26 287 / 26 997**. Чистые запрос/результат этой задачи без схем: 5609 → 821 токен. Сами schemas: 12 865 → 14 193 (full) или 5188 (analytics).

**Вывод из измерения:** full-профиль уменьшает каталог/рейтинг, но добавленные схемы и явная freshness увеличивают суммарный контент маленьких агрегатов. Нельзя заявлять экономию для всех задач полного профиля. Для отчётных сессий явный analytics-профиль снижает суммарный контент во всех четырёх измеренных сценариях. Полный профиль сохранён по умолчанию для совместимости; профиль нужно выбрать и переподключить клиент.

У 3.2.0 прямого рейтинга нет: baseline получает quantity sales и полные product cards, после чего клиент должен классифицировать/объединить article. Контроль проверен reference oracle, но сам старый LLM-процесс не запускался. Передача схем учитывается один раз **на независимую задачу**; сценарии исполнены последовательно на одном сервере, поэтому повторные источники могут быть тёплыми. Время controlled benchmark использует mocked API и не сравнимо с 188-секундным live API. Чтение всего export заново добавит весь массив в контекст — выборочный page read важен.

Повтор: `node scripts/benchmark-3.3.mjs`. Локальный baseline сохранён в игнорируемом `.tools/baseline-3.2.0`; его нужно сохранить для воспроизведения после переноса проекта. Артефакты benchmark содержат только численные метрики/контрольные итоги, без модельных выгрузок и ключей.
